# Kindora

## Personal AI Social Agents

> **Your AI finds the connection. You make the friendship.**

**GitHub Repository:** `kindora`

**Version:** V0.1.0  
**Status:** Experimental Open Source MVP  
**License:** MIT  
**Primary Goal:** Validate the AI-mediated human social interaction model.

---

# 0. 给 Claude Code 的最高优先级指令

你现在负责从零开发 **Kindora V0.1**。

Kindora 不是普通 AI Chat App，也不是 AI 陪伴软件，更不是 Dating App。

它的核心理念是：

> **每个用户拥有一个属于自己的 AI Social Agent。**
>
> Agent 理解自己的用户，并可以与另一个用户的 Agent 进行有限、受控的交流，从双方公开资料中发现共同点、判断潜在社交价值、生成破冰建议，然后把真人之间的交流交还给用户。

整个 V0.1 必须围绕下面这个闭环：

```text
User A
   ↓
Create Personal Agent
   ↓
Connect to Agent B
   ↓
Agent A ↔ Agent B
   ↓
Analyze Compatibility
   ↓
Generate Match Report
   ↓
Human A + Human B Consent
   ↓
Generate Icebreaker
   ↓
Human A ↔ Human B
   ↓
AI Assistance when requested
```

**不要把 V0.1 扩展成完整社交平台。**

# 1. 产品定位

## 1.1 一句话

> Kindora is an open-source personal AI social agent client that helps people discover meaningful human connections through agent-to-agent matching.

中文：

> Kindora 是一个开源的个人 AI 社交代理客户端，让用户的 AI Agent 先帮助发现共同点和潜在匹配，再帮助真人建立真实关系。

---

# 2. 核心原则

开发过程中始终遵守以下原则。

## 2.1 Human First

AI 辅助人类社交。

AI 不替代人类社交。

---

## 2.2 User-Owned AI

AI Agent 属于用户。

用户：

- 自己选择 LLM
- 自己提供 API Key
- 自己控制数据
- 自己决定 Agent 权限

---

## 2.3 Local First

用户的核心个人数据默认保存在本地。

不要建立中心化用户数据库。

---

## 2.4 Privacy First

只交换完成匹配所需要的最少信息。

---

## 2.5 Open Source First

V0.1 完全免费。

不加入：

- 会员
- 付费功能
- 广告
- 虚拟币
- 平台抽成

---

## 2.6 Validate Before Scale

先验证：

> Agent A ↔ Agent B → Human A ↔ Human B

是否真的有价值。

不要先建设：

- 全球用户网络
- DHT
- 推荐系统
- 大型服务器
- 社交 Feed

---

# 3. V0.1 成功标准

V0.1 不是以代码量或者页面数量判断成功。

必须能够验证：

> **AI Agent 是否可以提高两个陌生人建立真实交流的成功率。**

第一阶段目标：

- 20 个真实测试用户
- ≥10 次 Agent-to-Agent Match
- ≥5 次 Human Conversation
- ≥3 次用户主动再次使用
- ≥3 名用户明确认为 AI 帮助他们发现了原本不会认识的人

# 18. V0.1 网络设计

优先使用：

> WebRTC DataChannel

目标：

```text
Client A
   ↕
Encrypted P2P Connection
   ↕
Client B
```

但必须意识到：

> WebRTC 在真实互联网环境下需要 Signaling / STUN，部分网络还需要 TURN Relay。

因此：

V0.1 可以先提供：

### Mode A — Local / LAN

优先支持。

### Mode B — Manual WebRTC Signaling

允许用户手动交换 Offer / Answer。

### Mode C — Optional Signaling

代码结构必须预留未来 Signaling Server。

不要把网络层写死。

# 35. Prompt Injection 防御

# 69. 产品设计判断原则

如果一个功能：

### 不能帮助用户认识真正合适的人

删除。

如果一个功能：

### 只是为了增加社交平台常见功能

删除。

如果一个功能：

### 增加了复杂度但无法验证核心假设

删除。

如果一个功能：

### 可以推迟到 V0.2

推迟。
